    Loading an image file#

    buz::load_texture (asset_management/texture_loading.h) decodes an image file (png, jpg, bmp, tga, ...) and uploads it to the gpu.

    The path is relative to the content folder, with / between folders, so "my_game/textures/ball.png" loads content/my_game/textures/ball.png next to the executable.

    Textures come back as std::shared_ptr<buz::texture>. Keep them around somewhere, so that they stay loaded, and pass them to draw_sprite when you want to draw them to the screen.

    Loading can fail, usually because of a typo in the path. The engine then logs an error to the console and returns a magenta-and-black checkerboard instead of the texture. The game keeps running, and the sprite that should have shown your image is hard to miss.

    Put your images in content/<my_game>/textures. How the content folder ends up next to the executable is explained under Where your files go in Getting started.

    Procedural textures#

    buz::create_texture uploads raw rgba pixels (4 bytes per pixel), so you can build textures in code. For example, a grayscale texture from smooth noise:

    The fourth byte of each pixel is alpha: 255 is opaque and 0 is fully transparent. A texture is always a rectangle, so alpha is how you give a sprite another shape. For instances if you want to draw a circle, write alpha 255 for the pixels inside the circle and 0 for the pixels around it; drawn as a sprite, only the circle shows.

    Bitmap fonts#

    buz::renderer_2d::draw_text renders with a buz::font: one atlas texture holding every character in a fixed grid, in ascii order. The struct only describes the grid; the defaults match the engine's built-in atlas (content/fonts/font_8x8.png):

    Text rendering is sprite sheet drawing: each character becomes one quad showing its part of the atlas. To use your own font, draw an atlas image with the characters in a regular grid and fill in the buz::font fields (glyph_size, glyphs_per_row, first_character, glyph_count) to match your grid.
