    Keyboard and mouse state lives in buz::input; grab it from the engine. Every game function receives the engine, so there is no need to store a pointer to it:

    Held, pressed or released?#

    The three keyboard questions differ in when they are true:

    Use is_key_down for continuous actions (moving, shooting a beam) and was_key_pressed for one-shot actions (jump, toggle pause). With is_key_down a single tap would fire on every frame it spans.

    The available keys are the buz::key enum: letters (buz::key::a ...), digits (buz::key::num_0 ...), the arrow keys (left, up, right, down), space, enter, escape, shift, control, tab and backspace.

    Mouse#

    The same held/pressed/released trio exists for mouse buttons: buz::input::is_mouse_button_down, buz::input::was_mouse_button_pressed and buz::input::was_mouse_button_released, with buz::mouse_button::left / right / middle.

    Movement#

    Moving a character with the keyboard takes two steps: turn the keys that are held into a direction, then move the character along it. The first step is a key check per direction. The y axis points down, so up is negative:

    Adding that direction to the position every frame moves the character, but two problems show up as soon as you play:

    • Diagonals are faster. Holding w and d gives (1, -1), a vector about 1.41 long, so the character moves 41% faster diagonally. buz::normalize scales a vector to length 1. It has no answer for (0, 0), which has no direction, so only call it when a key is held.
    • The speed depends on the computer. on_update runs once per frame, so a fixed step per frame moves twice as fast at 120 frames per second as at 60. delta_seconds is the time since the previous frame: give the speed in pixels per second and multiply it by that time.
