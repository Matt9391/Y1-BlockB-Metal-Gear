    Guided exercise: Use the 3D template and write the animation player yourself (see Guided experiences).

    What you will build#

    You will build an animation player that makes a character play a walk, idle or other animation. It will keep track of playback time, repeat animations when needed and make transitions between animations smooth.

    buz::load_model loads animations as buz::keyframe_clip objects. Each clip contains a sequence of frames, sampled at 30 frames per second. Before starting, make sure these terms are clear:

    • A node is one part of the model's hierarchy. A node can have a parent, so moving the parent also moves its children.
    • A joint pose (buz::joint_pose) stores one node's translation, rotation and scale, relative to its parent.
    • A pose contains a joint pose for every node. It describes the whole character at one moment.
    • A frame stores one of those poses. An animation clip stores the sequence, such as all the frames of a walk cycle.

    Start by drawing a single pose. Once that works, you can change the pose over time to animate the character. The examples below are pseudocode; you will need to turn them into C++.

    Step 1: draw a single pose#

    Each joint pose describes a node relative to its parent. For example, the head's position is relative to the torso. To draw the head in the world, you also need the torso's transform.

    Work through the hierarchy so that every parent is handled before its children; the nodes of a buz::model are already stored in that order. Each node needs two things: a local transform, built from its joint pose, and its parent's world transform, which the loop worked out earlier. A root node has no parent, so use the character's placement instead: the transform that positions, rotates and scales the whole character in the world.

    Questions to answer before you write it:

    • The local matrix. A joint pose holds a translation, a rotation and a scale. In which order should they act on a vertex? With glm's column vectors (v' = M * v), in which order do you multiply the three matrices to get that?
    • Combining. Is a node's world transform parent * local or local * parent? Test your answer on the head: it should move when the torso turns, not the other way around.
    • Storage. Where do you keep the world transforms during the loop, so a child can read its parent's?

    Check: Draw the model in its rest pose, then draw frame 0 of a clip. Make sure every part is in the right place before adding playback.

    Step 2: calculate the pose between two frames#

    Playback time will often fall between stored frames. For example, at 30 frames per second, a time of 0.25 seconds corresponds to frame 7.5. That is halfway between frames 7 and 8.

    To find the pose at that time, interpolate between those two frames. Do this for every node: blend its translation and scale with lerp, and its quaternion rotation with glm::slerp.

    An amount of 0 gives the first pose; 1 gives the second. At 0.5, the result is halfway between them. Calculating a pose at a particular time is called sampling the clip.

    Rotations are stored as quaternions (buz::quat). Use glm::slerp here to interpolate along the shortest arc between the rotations. Ordinary component-wise lerp does not keep a quaternion normalized.

    For now, sample only times between the start and end of the clip. The next step handles what happens when playback reaches the end.

    Check: Sample at time 0, at exactly one stored frame and halfway between two frames. The first two should reproduce the stored poses; the third should produce a pose between them.

    Step 3: repeat the clip or hold its final pose#

    Frame 0 occurs at time 0. In this exercise, the final frame marks the end of the clip, so a clip with n frames has a duration of (n - 1) / fps seconds. For example, 31 frames at 30 frames per second span one second.

    Before sampling, adjust the playback time according to how the clip should end:

    For a one-second looping clip, a playback time of 1.25 seconds samples at 0.25 seconds. For a clip that plays once, it samples at 1 second and keeps showing the final pose.

    A seamless loop needs matching poses at the start and end. Wrapping the time alone will not hide a mismatch between them.

    Use utl::yes_no_t for the looping setting, following the engine's convention for yes/no parameters. These examples assume non-negative playback time and a clip with at least two frames. Handle a single-frame clip by returning its only pose, without calling fmod with a zero duration. An empty clip has no pose to sample.

    Check: Let a clip run past its duration. It should either repeat or hold its final pose, depending on the looping setting.

    Step 4: keep track of playback#

    Put the sampling and looping code into a player. It needs to remember the current clip, the elapsed playback time, the looping setting and the resulting pose.

    The early return in play() lets the game request the walk animation every update while the character is moving. Without it, each request would restart the animation at time 0. When the character stops, the game can request idle instead.

    Give each character its own player. Characters can share the model and clips while keeping separate playback times. To make guards walk out of sync, start them at different times or give them different starting offsets.

    Check: Request the same clip every update. It should keep playing. Request another clip and check that the new one starts at time 0.

    Step 5: make clip changes smooth#

    Switching directly from idle to walk can make the body snap into a new pose. To smooth the change, save the currently displayed pose when a new clip starts. Over a short transition, blend from that saved pose towards the new clip's sampled pose. Start with a transition of 0.2 seconds.

    Use the same per-node interpolation as in step 2. This time, you blend between the saved pose and the new animation's pose. The saved pose stays fixed during the transition while the new animation continues playing.

    Clamping blend_time keeps amount between 0 and 1. A transition duration of zero skips the blend and switches immediately.

    Check: Switch between idle and walk. Then switch again before a transition finishes. Each transition should start from the pose currently on screen.

    Levels#

    Complete the basic level before adding the intermediate and hard features.

    Basic

    • Draw every part of the soldier in the correct place, both in the rest pose and in a clip's frame.
    • Test sampling at time 0, at a stored frame and between frames.
    • Use slerp for rotations and lerp for translations and scales.
    • Repeat looping clips and hold the final pose of clips that play once.

    Intermediate

    • Keep playing when play() is called again with the current clip.
    • Blend from the displayed pose when switching clips.
    • Add playback speed so the walk animation can play faster when the character runs.
    • Attach an object to a node, such as a gun that follows the hand.

    Hard

    • Let the game check whether a one-shot clip has finished, for example before a guard resumes walking after a turn.
    • Play two clips on different parts of the body, such as walking with the legs while aiming with the arms.
