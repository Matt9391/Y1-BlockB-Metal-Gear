    Use json files for settings, save games and level data. buz::json is nlohmann::json, and buz::load_json and buz::save_json read and write the files.

    Reading a file#

    buz::load_json parses a whole file. When the file is missing or is not valid json, it logs an error and returns a discarded value, so check is_discarded() before you read from it:

    settings["volume"] works too, but only for a key that is certainly in the file. For a missing key it gives null, and converting null to a number throws an exception, which ends the game unless you catch it (see Diagnostics). value(key, fallback) returns the fallback instead. Use it for anything a player could have removed from the file by hand, or that an older version of your game did not write yet.

    Writing a file#

    Build a json value and pass it to buz::save_json. A relative path ends up in your game's save folder, saved/<game> next to the executable. buz::save_json creates missing directories, and it logs an error and returns false when it cannot write the file:

    Keep save games out of content/: every build copies your source content folder over the one next to the executable, replacing any file with the same name.

    The nlohmann documentation covers the rest of the json api: arrays, iteration and converting your own structs.
