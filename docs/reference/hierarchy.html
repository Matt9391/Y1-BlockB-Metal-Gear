Class Hierarchy
This inheritance list is sorted roughly, but not completely, alphabetically:
 Cbuz::aabb3D axis aligned box: the 3D version of rect, for collision checks. It is stored as its two extreme corners. The engine has no collision checks for it; the game writes them (see the collision guide)
 Cbuz::audioPlays sound effects and music with miniaudio (source/third_party/miniaudio). Supports .wav, .mp3 and .flac files
 Cbuz::colorRGBA color with components in the [0, 1] range
 Cbuz::debug_keysThe keys that switch the engine's debug views while the game runs. They work in every game, so your game does not check them itself; pick other keys here when you need these ones for the game
 Cbuz::debug_viewsThe debug views a world_renderer_3d draws with. buz::game_3d switches them with the engine's debug keys (engine_settings::debug_controls), so a game does not handle them
 Cbuz::engineOwns all engine systems and runs the main loop
 Cbuz::engine_settingsSettings the engine starts with
 Cbuz::fontA fixed-grid bitmap font: one atlas texture holding every character in a regular grid, in ascii order
 Cstd::hash< buz::texture_id >Lets a texture_id be the key of a std::unordered_map
 Cbuz::inputThe keyboard and mouse state of this frame
 Cbuz::keyframe_clipAn animation, sampled into poses at a fixed frame rate: every frame has a pose for every node of the model
 Cbuz::materialHow a mesh looks: a color, optionally times a texture, lit or not, optionally with see-through holes
 Cbuz::meshTriangles in gpu memory, ready to be drawn with world_renderer_3d::draw
 Cbuz::mesh_dataTriangles on the cpu, before they go to the graphics card: what buz::create_mesh uploads, and what buz::import_model reads from a file. Plain vectors, so you can build, merge or change them first
 Cbuz::mesh_vertexOne corner of a triangle of a mesh
 Cbuz::modelEverything in a glTF file: the nodes and the animations
 Cbuz::model_dataEverything in a glTF file, on the cpu: what buz::import_model reads. Merge, split or change the triangles before you upload them (buz::create_mesh); buz::load_model uploads every node as it is
 Cbuz::model_import_optionsRepairs for models that look right in the viewer they came from but not in the engine, typically files saved out of a web viewer (three.js and the like), which draws both sides of every triangle and repeats textures. Everything is off by default: a model made in Blender needs none of it
 Cbuz::model_nodeOne node of a model, as it was named and placed in Blender
 Cbuz::model_node_dataOne node of a model on the cpu, as buz::import_model reads it: a model_node whose triangles are not on the graphics card yet
 Cbuz::node_transformWhere a node of a model sits relative to its parent node: its translation, rotation and scale. A pose (a frame of an animation, or get_rest_pose) is one node_transform for every node
 Cbuz::playableWhat engine::run runs. Every frame the engine calls update, then render_world, then render_screen
 Cbuz::gameThe base class of buz::game_2d and buz::game_3d: a game derives from one of those two, depending on whether its world is 2D or 3D
 Cbuz::game_2dThe base class of a game with a 2D world: derive your game from it
 Cbuz::game_3dThe base class of a game with a 3D world: derive your game from it
 Cbuz::rect2D axis aligned rectangle, used for collision checks
 Cbuz::renderer_2dThe drawing functions shared by world_renderer_2d and screen_renderer
 Cbuz::screen_rendererDraws on top of the world in plain window pixels: score, lives, menus. It ignores the world's camera, so the hud stays put while the level scrolls underneath it
 Cbuz::world_renderer_2dDraws the 2D game world: everything that lives in the level and moves when the camera moves
 Cbuz::screenshot_saverSaves the frame being drawn as a png once it is finished
 Cbuz::sprite_instanceOne sprite for draw_sprite_instances: everything draw_sprite takes, minus the texture (all instances share one)
 Cbuz::surface_shadingWhich shaders draw a world_renderer_3d's meshes, and how they filter textures. The defaults are the built-in shaders, shaders/diffuse_vs.hlsl and shaders/diffuse_ps.hlsl. A shader is named by its file name without .hlsl; put your own next to them in /shaders.  Cbuz::textureA 2d image living in gpu memory, ready to be drawn
 Cbuz::texture_idNames an image without loading it: an image file in the content folder, or an image inside a model file (a .glb carries its textures inside)
 Cbuz::timerMeasures elapsed wall clock time with high precision
 Cbuz::windowThe window the game draws into. It keeps the size it opened with (engine_settings::window_width and window_height):
 Cbuz::world_renderer_3dDraws the 3D game world, through a camera
