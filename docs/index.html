    How a game starts

    What the engine does for you

    Every game needs the same groundwork before there is anything to play: a window to draw in, a loop that runs once per frame, input from the keyboard and mouse, and a way to draw and play sound. The engine provides that groundwork, so the code you write is about the game itself.

    Your game connects to the engine through a class that derives from buz::game_2d, like my_game here, or from buz::game_3d for a 3D world. Its constructor loads what the game needs while it runs, in this case the texture of a ball. From then on the engine calls the class every frame: in on_update the game reacts to input and moves things, and in on_render_world and on_render_screen it draws them, each with the renderer it gets. This example has nothing to move, so it only draws.

    In a real game, this class doesn't do all the work itself. The player, the enemies and the level are usually classes of their own, in separate files, and the game class creates them and updates them every frame. All of it is plain C++; there is no editor or scripting language.

    Your template

    A template is a CMake project that already contains the engine's source code, a small game that runs, and scripts to build, run and package your games. Run that game first, then change it or add your own next to it.

    Sharing your game

    Sharing your game >

    • Windows

      package.bat -game=awesome_gamepackage/awesome_game-windows.zip

      The game and its content folder. Extract the archive and run the game.

    • Linux

      ./package.sh -game=awesome_gamepackage/awesome_game-linux.tar.gz

      The game and its content folder. Extract the archive and run the game.

    • The web

      package.bat -game=awesome_game -webpackage/awesome_game-web.zip

      The game as a web page. Upload the zip to itch.io as an HTML game.
